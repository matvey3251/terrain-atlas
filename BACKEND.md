# Backend и доступность данных

Проверка 2026-11-14: Node fetch и PowerShell Invoke-WebRequest внутри sandbox завершаются EACCES / запретом доступа к сокету для обоих публичных Overpass. Это ограничение сетевой среды, а не доказанная ошибка CORS. Вне sandbox overpass-api.de не ответил за 20 секунд. Заголовки CORS получить не удалось; доступ из браузера нужно проверять отдельно.

## Текущая архитектура

Sites публикует статический dist. Браузер делает запросы к Overpass и AWS DEM напрямую. Backend не развернут. Локальный proxy не добавлен: он не исправляет ограничения сети и не будет работать на статическом хостинге. Ошибки провайдеров должны отображаться пользователю; отсутствие ответа не означает отсутствие зданий. Загруженные результаты нельзя выдавать за актуальную геодезическую съемку.

## Production

Для нагрузки нужен отдельный HTTP backend либо переход на Worker-деплой Sites. Требуются ограничение площади и сложности запросов, очередь, отмена, кэш по bbox/версии источника, ограничение частоты по клиенту и общий бюджет запросов. Возвращать дату источника и загрузки, таймауты и частичные ошибки явно. Не использовать proxy произвольных URL: только allowlist фиксированных источников. При росте нагрузки — собственный Overpass/региональные OSM extracts и собственный кэш DEM; бесплатность исходных данных не означает бесплатность вычислений и трафика. Не обходить лимиты публичных серверов автоматическим бесконечным переключением.

Для надежного офлайн-повтора полезен импорт ранее сохраненного исходного GeoJSON/DEM с сохранением происхождения; это отдельная функция, пока не реализована. Статический сайт не обеспечивает SLA внешних сервисов.

Дополнение: вне sandbox private.coffee также не ответил за 20 секунд. Успешный HTTP-запрос из PowerShell в этой среде не подтвержден.
